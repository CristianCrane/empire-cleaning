# The test site deploys once a night

Render's auto-deploy is off on the test site's services. A scheduled Action deploys them once a night instead, each at `main`'s newest commit that passed CI and only when its files changed (ADR-0036), and runs by hand when a change must go out at once. Render's build minutes are capped at 500 a month: deploying per push had used about 703 status-minutes by 2026-11-27, and with ADR-0036's filters #581 still estimated about 421 billed minutes a month, close to the cap. November replayed through the Action's own rule, one run a night, comes to 94 status-minutes (about 67 billed, at #581's 0.71 billed minutes to one status-minute), and that's an upper bound, as commits before #581 had no filter. The user said on 2026-11-27: "current usage patterns align with batched nightly pushes. id still have the option to deploy manually if i really needed it immediately."

This rules out **deploying per push**, filters or not, as it stays close to the cap, and **a `test-site` branch that Render auto-deploys from**, pushed to nightly: Render's docs don't say how a push of many commits is judged against a `buildFilter` (render.com/docs/monorepo-support), and a wrong guess would leave a service stale with nothing red. It supersedes ADR-0036's and ADR-0020's trigger, a deploy from `main` once each push's CI passes. How it runs, and how to deploy at once: `README.md`, Test site.
